# Proposal: GitLab MCP Server

## Why

Для эффективной работы AI-ассистентов (Claude Code, Cursor и др.) с кодовой базой и процессами в GitLab необходим специализированный MCP-сервер (Model Context Protocol). Существующие решения либо перегружают контекст модели десятками низкоуровневых REST API методов, либо не обеспечивают гибкого разграничения прав и ролей, либо требуют знания внутренних числовых ID проектов. Разработка модульного MCP-сервера решает проблему контролируемого, безопасного и контекстно-эффективного взаимодействия агентов с GitLab.

## What Changes

Создание нового MCP-сервера на базе TypeScript и официального `@modelcontextprotocol/sdk` с транспортом `stdio`:
- **Иерархическая конфигурация**: поддержка настройки через CLI-аргументы, переменные окружения и `.env` файлы с приоритетом CLI > ENV > `.env` > defaults.
- **Модульная система инструментов**: возможность включать/отключать наборы инструментов через флаг `--tools` (`mr`, `repository`, `ci`, `settings` или их комбинации).
- **Мультипроектность и обнаружение**: прозрачная работа как с числовыми ID проектов, так и с путями `namespace/project-name`, опциональный `default_project` и инструмент поиска проектов `gitlab_search_projects`.
- **Merge Requests**: создание MR, получение списка, агрегированное чтение MR (сводка, диффы, треды обсуждений, статус пайплайнов) и добавление комментариев.
- **Работа с файлами репозитория**: чтение содержимого файлов на любых ветках/тегах и просмотр дерева репозитория.
- **CI/CD пайплайны**: мониторинг пайплайнов, получение детального статуса с опцией `show_trace`, которая автоматически собирает хвосты логов упавших джоб с очисткой от ANSI-кодов.
- **Управление настройками проекта**: управление защищенными ветками и тегами, изменение ветки по умолчанию, общих настроек проекта, параметров MR и CI/CD.

## Capabilities

### New Capabilities
- `server-configuration`: загрузка и валидация конфигурации сервера из CLI-флагов, переменных окружения и .env файлов, фильтрация инструментов на основе флага `--tools`.
- `project-discovery`: разрешение идентификаторов проектов (ID или path_with_namespace), fallback на проект по умолчанию и поиск проектов.
- `merge-requests`: управление и просмотр Merge Requests, включая агрегированное получение данных, диффы, треды комментариев и создание MR.
- `repository-files`: чтение файлов и навигация по дереву файлов репозитория на произвольных ветках, тегах или коммитах.
- `ci-pipelines`: мониторинг статусов пайплайнов, детальный просмотр с автоматическим извлечением и очисткой логов упавших джоб при запросе `show_trace`.
- `project-settings`: управление настройками проекта, защищенными ветками и тегами, веткой по умолчанию, политиками слияния MR и CI/CD.

### Modified Capabilities
Никаких изменений существующих возможностей (проект инициализируется с нуля).

## Impact

- Создание нового автономного Node.js / TypeScript приложения с CLI точкой входа.
- Внешние зависимости: `@modelcontextprotocol/sdk`, `@gitbeaker/rest` (или нативный `fetch`), `dotenv`, библиотеки для парсинга аргументов (например `commander` или `yargs`), очистки ANSI (`strip-ansi`) и валидации схем (`zod`).
- Интеграция с локальными клиентами MCP через stdio (Claude Desktop, Cursor, Claude Code).
