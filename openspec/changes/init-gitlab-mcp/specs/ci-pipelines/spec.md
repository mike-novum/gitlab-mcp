# Spec Delta

## Purpose

Мониторинг статусов CI/CD пайплайнов в GitLab, получение подробной информации о стадиях и джобах, а также автоматическое извлечение и очистка логов упавших джоб для диагностики сбоев агентом.

## ADDED Requirements

### Requirement: Получение списка пайплайнов
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_list_pipelines`, позволяющий просматривать последние пайплайны проекта с возможностью фильтрации по ветке/тегу (`ref`), статусу (`success`, `failed`, `running`, `pending`) и ограничению количества результатов.

#### Scenario: Фильтрация пайплайнов по ветке и статусу
- **WHEN** агент вызывает `gitlab_list_pipelines(ref="main", status="failed", limit=5)`
- **THEN** сервер возвращает последние 5 упавших пайплайнов ветки `main` с их `id`, `status`, `ref`, `sha`, `created_at` и `web_url`

### Requirement: Получение детальной информации о пайплайне
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_get_pipeline`, возвращающий подробную информацию о пайплайне, включая перечень всех стадий и входящих в них джоб со статусами и длительностью выполнения.

#### Scenario: Просмотр джоб пайплайна
- **WHEN** агент запрашивает детали пайплайна по его `pipeline_id`
- **THEN** ответ содержит общее состояние пайплайна, список стадий и для каждой джобы: `id`, `name`, `stage`, `status`, `duration`

### Requirement: Автоматический сбор логов упавших джоб
Сервер ДОЛЖЕН при передаче параметра `show_trace=true` в запросе `gitlab_get_pipeline` автоматически находить упавшие джобы (`failed`), выгружать их логи, очищать лог от ANSI-последовательностей и возвращать срез последних строк лога.

#### Scenario: Запрос упавшего пайплайна с show_trace
- **WHEN** пайплайн имеет статус `failed`, и агент вызывает `gitlab_get_pipeline(pipeline_id=123, show_trace=true)`
- **THEN** сервер запрашивает логи для каждой упавшей джобы, удаляет терминальные ANSI escape-коды и прикрепляет последние 200 строк каждого лога к ответу

#### Scenario: Запрос успешного пайплайна с show_trace
- **WHEN** пайплайн завершился успешно (`success`), и агент вызывает `gitlab_get_pipeline(pipeline_id=124, show_trace=true)`
- **THEN** сервер возвращает стандартную структуру пайплайна без выполнения дополнительных запросов к логам

### Requirement: Перезапуск упавших джоб и пайплайнов
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_retry_pipeline`, позволяющий перезапустить выполнение упавшего пайплайна или повторить только неуспешные джобы.

#### Scenario: Перезапуск упавшего пайплайна
- **WHEN** агент вызывает `gitlab_retry_pipeline(pipeline_id=123)`
- **THEN** сервер инициирует повторный запуск в GitLab и возвращает обновленный статус пайплайна
