# Spec Delta

## Purpose

Управление и инспекция Merge Requests в GitLab, включая фильтрацию списка, создание новых MR, агрегированное получение деталей с диффом и тредами обсуждений, а также добавление комментариев.

## ADDED Requirements

### Requirement: Получение списка Merge Requests с фильтрацией
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_list_mrs` для получения списка MR с возможностью фильтрации по состоянию (`opened`, `closed`, `merged`, `all`), целевой ветке, автору и ревьюеру, с поддержкой пагинации.

#### Scenario: Получение открытых MR в целевую ветку
- **WHEN** агент вызывает `gitlab_list_mrs` с параметрами `state="opened"` и `target_branch="main"`
- **THEN** сервер возвращает список открытых MR, направленных в ветку `main`, с полями `iid`, `title`, `source_branch`, `target_branch`, `author`, `created_at`

### Requirement: Агрегированное получение деталей Merge Request
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_get_mr`, возвращающий подробную информацию о MR и позволяющий опционально включать дифф изменений, треды обсуждений и статус пайплайна в рамках одного вызова.

#### Scenario: Запрос MR с включением диффа и комментариев
- **WHEN** агент вызывает `gitlab_get_mr` с `mr_iid=10`, `include_diff=true` и `include_discussions=true`
- **THEN** ответ содержит метаданные MR, список измененных файлов с их патчами/диффами и иерархический список тредов обсуждений

#### Scenario: Запрос деталей MR без дополнительных опций
- **WHEN** агент вызывает `gitlab_get_mr` с `mr_iid=10` без дополнительных флагов
- **THEN** ответ содержит метаданные MR, описание и верхнеуровневый статус последнего пайплайна без выгрузки полного диффа и всех тредов

### Requirement: Ограничение размера выгружаемого диффа
Сервер ДОЛЖЕН предотвращать переполнение контекста агента при запросе больших диффов, ограничивая общий объем возвращаемого диффа и предоставляя возможность запросить дифф конкретного файла.

#### Scenario: Превышение максимального лимита строк диффа
- **WHEN** общий объем изменений в MR превышает установленный лимит строк (по умолчанию 500 строк)
- **THEN** сервер обрезает дифф, указывает флаг `diff_truncated=true` и возвращает список всех измененных файлов с предложением запросить конкретный файл

#### Scenario: Запрос диффа отдельного файла в MR
- **WHEN** агент вызывает `gitlab_get_mr` с указанием параметра `file_path="src/index.ts"`
- **THEN** сервер возвращает дифф только для указанного файла

### Requirement: Создание Merge Request
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_create_mr`, позволяющий создать новый Merge Request с указанием исходной и целевой веток, заголовка, описания, черновика (draft), меток (labels) и ревьюеров.

#### Scenario: Успешное создание MR
- **WHEN** агент вызывает `gitlab_create_mr` с валидными `source_branch="feature/test"`, `target_branch="main"`, `title="Add test feature"`
- **THEN** в GitLab создается новый MR и возвращаются его `iid`, `web_url` и текущее состояние

### Requirement: Добавление комментариев и ответов в треды MR
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_create_mr_note`, позволяющий оставить общий комментарий к MR либо ответить в существующий тред обсуждения по его `discussion_id`.

#### Scenario: Создание нового общего комментария к MR
- **WHEN** агент вызывает `gitlab_create_mr_note` с `mr_iid=10` и `body="LGTM!"` без `discussion_id`
- **THEN** в MR создается новый комментарий верхнего уровня

#### Scenario: Ответ в существующий тред обсуждения
- **WHEN** агент вызывает `gitlab_create_mr_note` с `mr_iid=10`, `discussion_id="abc123xyz"` и текстом ответа
- **THEN** комментарий добавляется в указанный тред обсуждения

### Requirement: Добавление комментариев к строкам кода в диффе
Сервер ДОЛЖЕН предоставлять возможность оставлять комментарии к конкретным строкам кода в диффе Merge Request, автоматически определяя актуальные diff_refs (base_sha, start_sha, head_sha) из метаданных MR, если они не переданы агентом явно.

#### Scenario: Добавление замечания к измененной строке кода
- **WHEN** агент вызывает создание комментария с параметрами `mr_iid=10`, `path="src/index.ts"`, `line=42` и текстом замечания
- **THEN** сервер запрашивает актуальный diff_refs для MR и создает тред обсуждения, привязанный к указанному файлу и строке

#### Scenario: Указание строки в старой версии файла
- **WHEN** комментарий относится к удаленному или замененному коду, и агент передает `old_line=30` вместо `new_line`
- **THEN** тред обсуждения создается с привязкой к `old_line` в `old_path`
