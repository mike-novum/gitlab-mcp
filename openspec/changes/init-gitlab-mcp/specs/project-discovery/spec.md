# Spec Delta

## Purpose

Обеспечение гибкой идентификации проектов в GitLab (по числовому ID или пути namespace/project), поддержка проекта по умолчанию и поиск репозиториев для исключения ошибок агента.

## ADDED Requirements

### Requirement: Универсальное разрешение идентификатора проекта
Сервер ДОЛЖЕН принимать идентификатор проекта как в виде целого числа (ID проекта), так и в виде строки пути с неймспейсом (например `group/subgroup/project`), прозрачно выполняя необходимое URL-кодирование для GitLab API.

#### Scenario: Запрос с использованием пути с неймспейсом
- **WHEN** агент вызывает инструмент с параметром `project_id="my-org/backend-service"`
- **THEN** сервер успешно преобразует путь в URL-encoded формат (`my-org%2Fbackend-service`) и выполняет запрос к API GitLab

#### Scenario: Запрос с использованием числового ID
- **WHEN** агент вызывает инструмент с параметром `project_id=42819`
- **THEN** сервер использует числовой ID напрямую при обращении к API GitLab

### Requirement: Использование проекта по умолчанию
Сервер ДОЛЖЕН использовать проект по умолчанию, если параметр `project_id` опущен в вызове инструмента, при условии что `default_project` настроен в конфигурации.

#### Scenario: Вызов инструмента без указания проекта при наличии default_project
- **WHEN** в конфигурации сервера задан `default_project="org/repo"`, и агент вызывает инструмент без указания `project_id`
- **THEN** сервер выполняет операцию в контексте проекта `org/repo`

#### Scenario: Вызов инструмента без указания проекта при отсутствии default_project
- **WHEN** в конфигурации сервера `default_project` не задан, и агент вызывает инструмент без `project_id`
- **THEN** инструмент возвращает понятную ошибку о том, что требуется указать `project_id` или настроить проект по умолчанию

### Requirement: Поиск проектов по имени и описанию
Сервер ДОЛЖЕН предоставлять инструмент `gitlab_search_projects`, позволяющий агенту находить проекты по текстовому запросу и получать их ID, полный путь и описание.

#### Scenario: Поиск проекта по ключевому слову
- **WHEN** агент вызывает `gitlab_search_projects(query="billing")`
- **THEN** сервер возвращает список совпавших проектов с полями `id`, `name`, `path_with_namespace`, `description` и `web_url`
